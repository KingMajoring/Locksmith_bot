{% comment %} Camera-or-gallery photo picker for one named slot — used by job_complete, job_photo_upload and job_access_method. Args: kind (e.g. "front_of_car"), required (bool), label (str — the same text used in the "Add at least one photo: X" message, so the client-side check reads the same as the server-side one), existing_urls (already-uploaded photo URLs for this slot, e.g. after a page reload mid-job). order_no comes from the including template's own context — not passed explicitly, since {% include %} shares context by default. Each photo uploads immediately via fetch as soon as it's taken/picked (see base.html), instead of travelling with the surrounding form's own final submit — a completion submit carrying every slot's photos in one multipart request was the real shape of the "stuck on save" bug fixed earlier by raising the server's request timeout; uploading one small photo at a time removes the reason that timeout was ever needed. The file input itself only ever exists to trigger the OS picker — nothing about it is submitted with the surrounding form. "Take photo" sets capture=environment on it first so the OS opens the camera directly instead of the file/gallery chooser. Visually hidden via CSS (.photo-file-input), not the `hidden` attribute — a display:none file input silently refuses to open on some mobile browsers when clicked programmatically (confirmed live on both iOS Safari and Android Chrome). {% endcomment %}
